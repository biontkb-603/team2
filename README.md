# 마냉이 (My Fridge)

냉장고 속 식재료와 유통기한을 관리하고, 가진 재료로 만들 수 있는 요리를 추천하고, 부족한 재료는 쇼핑몰 검색으로 이어 주는 모바일 웹 앱입니다.
서버와 데이터베이스 없이 브라우저에서만 동작하는 **데모 앱**이며, 모든 데이터는 가상입니다.

> **현재 상태 (2026-11-12)** — UI 단계 완료(시안 25장을 화면으로 구현, 고정 샘플 데이터 사용). 기능 단계(저장·계산·추천·로그인 연결)는 아직 시작 전이라, 화면은 눌러 볼 수 있지만 입력한 값은 저장되지 않습니다. 진행 상황은 [`task.md`](task.md)에 있습니다.

## 빠른 시작

필요한 것: [Node.js](https://nodejs.org) 24 이상(npm 11)

```bash
cd app
npm install
npm run dev
```

터미널에 나온 주소(기본 `http://localhost:5173`)를 브라우저에서 엽니다. 모바일 앱 화면이라 폭이 최대 430px인 프레임으로 보이고, 개발자 도구의 모바일 보기(360~430px)로 보면 더 비슷합니다.

화면 흐름은 이렇게 눌러 보면 됩니다.

1. 로그인 화면에서 **아무 값이나 넣고 로그인**(아직 실제 인증은 없습니다) → 홈
2. 아래 탭: 홈 · 냉장고 · 추천 · 장보기 · 마이페이지
3. 이번 범위에 없는 기능(커뮤니티, 냉장고 연동, 가격 비교 등)은 누르면 **"곧 지원 예정이에요"** 안내만 뜹니다.

개발 중에만 쓰는 둘러보기 페이지도 있습니다(마무리 단계에서 지웁니다).

| 주소 | 내용 |
|---|---|
| `/_screens` | 만든 화면 목록과 바로가기 |
| `/_components` | 공통 컴포넌트(버튼, 입력창, 배지 등) 모음 |

## 명령어

모두 `app/` 폴더에서 실행합니다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run build` | 타입 검사 후 배포용 빌드(`dist/`) |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run lint` | 코드 검사(oxlint) |
| `npm test` | 단위 테스트(Vitest). 파일 하나만: `npx vitest run src/lib/dday.test.ts` |
| `npm run e2e` | 브라우저 점검(아래 참고) |

## 브라우저 점검 (`npm run e2e`)

실제 크롬을 띄워 화면을 눌러 보며 확인하는 점검 18개입니다. 로그인부터 로그아웃까지의 전체 흐름, 화면별 동작, 하단 탭 표시·"<" 이동, 요소가 화면 밖으로 넘치지 않는지(360×640과 408×880) 등을 봅니다.

**필요한 것**: Google Chrome(또는 Chromium). 자동으로 찾지 못하면 경로를 알려 주세요.

```bash
CHROME_PATH="/path/to/chrome" npm run e2e
```

**사용법**

```bash
npm run e2e                  # 전체: 빌드 → 서버 시작 → 18개 실행 → 서버 종료
npm run e2e -- --no-build    # 이미 빌드했다면 빌드 생략
npm run e2e -- home list     # 이름이 맞는 점검만 (e2e/<이름>.mjs)
```

결과는 `PASS 이름` / `FAIL 이름`으로 나오고, 실패하면 이유가 함께 출력되며 종료 코드가 1입니다(없는 이름이면 2, 모두 통과하면 0).

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `CHROME_PATH` | 흔한 설치 위치를 자동 탐색 | 크롬 실행 파일 경로 |
| `E2E_PORT` | `4173` | 점검용 서버 포트(이미 쓰는 중이면 바꾸세요) |
| `E2E_BASE` | `http://localhost:<포트>` | 이미 떠 있는 서버 주소를 직접 지정 |

점검 목록: `flow`(전체 흐름) · `bounds`(화면 밖 넘침) · `check`(모든 화면의 탭·"<") · `font`(글꼴 적용) · `login` · `signup` · `home` · `status` · `list` · `add` · `photo` · `rec` · `detail` · `shop` · `my` · `fav` · `noti` · `notice`

**시안과 나란히 비교하기** — 점검이 저장한 화면 캡처(`app/e2e/.out/`, git에는 올라가지 않음)를 시안과 붙여 볼 수 있습니다(Pillow 필요: `pip3 install pillow`).

```bash
# 앱 캡처, 시안 화면 번호, 저장할 파일
python3 e2e/compare.py e2e/.out/ls.png 09 e2e/.out/side-09.png
```

왼쪽이 시안(`design/screen-09.png`), 오른쪽이 앱입니다.

├─ design/                       시안을 화면별 이미지로 뽑은 것(screen-01~25.png), 디자인 토큰(tokens.md)

   ├─ src/
   │  ├─ pages/                  화면(한 파일에 한 화면)
   │  ├─ components/             공통 UI (TopBar, Button, Input, Dialog, Switch, Toast …)
   │  ├─ data/mock.ts            시안에서 옮긴 샘플 데이터
   │  ├─ lib/                    순수 함수와 단위 테스트 (D-day 규칙, 쇼핑몰 주소)
   │  ├─ screens.ts              시안 화면 ↔ 주소 표 (탭 표시·"<" 동작)

## 알아 둘 약속

- **화면은 시안(`마냉이 1차.pdf`)을 따릅니다.** 시안과 다르게 만든 부분은 `task.md`의 "시안 차이 기록"에 이유와 함께 적습니다.
- **용어**: "유통기한"(시안 문구). **3일 이내**면 "임박"이고, 당일은 "오늘까지", 지난 것은 "기한 지남"으로 표시합니다. 홈·냉장고·알림이 같은 기준을 씁니다.
- **범위 밖 기능**(커뮤니티, 냉장고 연동, 가격 비교·장바구니, 사진 AI 인식, 내 정보·취향 수정)은 메뉴·버튼을 시안대로 보이게 두고 누르면 "곧 지원 예정이에요"만 띄웁니다. 화면 자체는 만들지 않습니다.
- **쇼핑몰 바로가기**는 검색어를 넣고 쇼핑몰(쿠팡·네이버 스토어·마켓컬리·이마트몰)을 누르면 그 쇼핑몰의 검색 페이지를 새 탭으로 엽니다. 주소는 사이트 개편으로 바뀔 수 있어 시연 전에 한 번 열어 확인하세요(`app/src/lib/malls.ts`).
- 로고와 SNS 아이콘은 원본이 없어 시안 이미지에서 잘라 썼습니다(`app/src/assets/`). 원본을 받으면 같은 파일명으로 바꾸면 됩니다.

## 작업 방법 (git)

- `main`에서 바로 작업하지 않고 `feat/<작업ID>-<이름>`(예: `feat/U-05-login`) 브랜치에서 작업한 뒤 `main`에 합칩니다.
- 작업 ID 하나에 커밋 하나, 메시지는 `U-05: 로그인 화면 구현` 형식입니다.
- 작업이 끝나면 `task.md`의 상태 표시와 진행 로그를 같은 커밋에 함께 고칩니다.
- 화면을 고쳤다면 `npm run lint`, `npm test`, `npm run e2e`를 통과시킨 뒤 올립니다.
